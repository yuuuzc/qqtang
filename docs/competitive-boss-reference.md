# 竞技模式 Boss 候选与召唤参考

日期：2026-08-13（Asia/Shanghai）

`evidence/competitive-boss-reference-v2.json` 是以原版 5.2 客户端为主表、历史资料为旁证的
机器可读参考。它不是运行时掉率配置。最重要的模型边界是：**选择地图只得到该地图允许的
Boss 候选，不能直接把普通竞技改成 Boss 局。** 服务端必须在开局前冻结有效成员快照，逐人
核验召唤条件；不满足时继续原生普通/特殊规则，满足时才生成一个本局 Boss 激活结果。

当前所有已证实竞技 Boss 局每场最多一个具名 Boss 和一个 Boss 实体。协议数组容量及共享
构造器的多槽能力不是多 Boss 玩法证据。同一地图若有多个候选同时满足，而客户端优先级尚未
恢复，服务端应拒绝歧义开局，不得随意选择或同时生成。

## 客户端完整性审计

原版 `itemCFG` 明确给出九个具名物品召唤身份：大副、虎克船长、大盗/圣诞/鬼仆格里芬、
小/大年兽、小小罗和鲁尼；再加上原版实录确认的免费水手，当前客户端证实的具名竞技 Boss
共十个。`卡 BOSS` 只是规则1地图标题；规则8 `CREATE_NPC_BOSS` 是通用动态实体能力；
Boss纪念背景只重复水手/格里芬/绿茵三组，三者均不构成新增 Boss。未开放资源若没有闭合的
客户端名称、召唤物和地图分支，只记为资源存在，不能凭外观猜出第十一个 Boss。

所有“每人”规则仍需用 5.2 请求和库存变化实测；召唤物是否消耗、何时消耗是独立事务，
不能在资格检查时顺便扣除。物品描述明确说30个藏宝图碎片用于合成藏宝图，真正召唤大副的是
藏宝图，因此不会把碎片直接作为入场替代。资料中的人数限制、掉率及2007限时免费活动不进入
运行时。十个候选现均进入类型化运行目录：服务端只在唯一候选满足时激活，并对一个原生实体
执行统一队伍和 Boss 结算；各历史地图关联、HP 与奖励库存仍按来源标注为参考或本地重建，
不能称为客户端内置官方表。矿洞11等规则1 Boss 的空降事件由服务端独立调度：客户端已证明
同形 `0x10E1` 生产器只由踢炸弹规则安装，不能把规则2上行伪装成规则1的客户端能力。Boss
自身攻击则走另一条已闭合的原生链：`BOSS_INFO.Skills` 驱动仲裁客户端产生 `0x1169/0x116A`；
通用 Boss 使用客户端实现的1..4程序，大副/虎克使用专用1..9程序。水面11的 `.map` 物品表虽空，
但原版录像明确有墙内物品，现由集中配置恢复相邻水面系列的16项池。证据边界详见
`evidence/competitive-boss-runtime-v1.md`。
