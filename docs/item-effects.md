# 特殊道具与效果规则

日期：2026-08-14（Asia/Shanghai）

机器可读清单是 [`data/qqt_special_item_effects.json`](../data/qqt_special_item_effects.json)。它由
`cmd/qqt-item-effects` 从当前 v848 `itemCFG` 和 v110 `DealProp2/propdescrip` 重建，不能手工维护
另一份相互漂移的 ID 表。每条规则都有来源、触发点、适用模式、参数、实现状态和证据说明。

## 商城“功能道具”完整清单

商城原名统一使用“功能道具”，不是“功能卡”。原版把该页拆成 `platform / item / card` 三个独立
启用槽；服务端保留这个模型，不按名称为每个道具另造开关。完整 81 项机器清单由
`cmd/qqt-function-items` 从安装客户端生成到 [`data/qqt_function_items.json`](../data/qqt_function_items.json)：

- 已有明确触发链的项目包括29项对局快捷栏、资格/持有规则中的已证实部分、喇叭、求婚、
  婚戒显示和砸蛋等；精确数量以机器清单的`status`为准，不把只有商品说明的视觉效果算作已实现；
- 12 项只是任务或合成材料，保存在背包中但没有独立主动效果；
- 13 项仍缺协议或数值证据：竞技场参赛点、两张抽奖卡、三张糖泡天书、甜蜜爱情卡、
  五枚婚戒的亲密度数值以及客户端缺少第六档图像的永恒爱神之戒。

原客户端商品配置与动作反编译共同证明闪电卡199、贝氏弯刀467、少林金刚脚468不是需要主动装备
的角色`platform`槽，而是按有效背包所有权在对应地图动作中被动生效。服务端在竞技开局一次性
投影最多8名参与者的`PlayerID -> effect mask`，静态客户端适配器缓存后直接消费原生动作：199
只在机械`0x1159`普通/组合放泡路径渲染闪电；467/468只在足球`0x0FB4/0x139C`触碰踢泡路径
渲染四方向银弧/冲击，可同时显示。三者不改伤害、速度、力度或原消息，收藏柜状态2是关闭开关。
详见 EVID-276。包子卡204是另一条已闭合规则：仅在竞技开局解析问号角色时先独立做一次50%判定，命中后
使用包子头RoleID 10；未命中再
从排除RoleID 10的其余竞技随机池选取。最终只通过普通GAME_BEGIN人物快照同步具体角色，探险与
显式选择角色不受影响。

主动砸蛋使用双向传输命令 `0x00FE`；其请求正文为 `0x0BDB REQUEST_BREAK_EGG`，响应正文为
`0x0BDC RESPONSE_BREAK_EGG`。蛋9001..9004、
锤9011..9013与奖励在同一SQLite事务扣发，失败全部回滚；响应前先推送三类绝对库存行，保证原版
结果窗口立即读到新数量。原服奖励池没有随客户端安装，当前
[`configs/break-egg-rewards.json`](../configs/break-egg-rewards.json) 是可编辑的本地重建策略，文档和
代码均不得把它描述成官方掉率。糖泡卡4237/翅膀卡4238也没有挪用商品999的水果机流程。

## 快捷栏模式边界

`PLAYER_GAME_INFO.NewItems` 只投影当前角色已装备、仍有效且与房间类型兼容的账号消耗品：

- 竞技道具场专用：`20003, 20006, 20007, 20010..20019, 20021..20026`；
- 探险专用：`20027, 20028, 20030..20040（当前表中无 20029）, 20042..20045, 20047, 20048, 20050, 20100, 20101`；
- 两种模式通用：陷阱 `20008/20009`、万能药水 `20020`、万能药剂 `20046`、礼花 `20058..20064`；
- 竞技无道具场和抢宝场不投影账号快捷栏。

服务端负责模式校验、账号所有权、数量扣减、向同局玩家广播 `0x1175` 和返回绝对剩余数量；
原版客户端负责瞬时动画、移动/糖泡属性和状态效果。急救包、医疗包与复活卡触发后的生存状态仍由
正式的救人/复活事件进入对局状态机，不能仅凭一个 ItemID 猜目标玩家。

## 已接入的服务端规则

- `99` 单人探险卡：探险单人开局资格；持有即生效，不按场次消耗。
- `100` 防踢卡：准备房被踢权限；紫钻身份具有同等保护。房主踢人使用类型化
  `REQUEST/RESPONSE_KICKOFF_PLAYER`，保护命中时返回失败且不改变房间状态。
- `121` VIP卡：竞技获胜积分乘 2；平局/失败不乘。竞技地图门槛直接读取原版
  `map/mapDesc.py` 的积分字段；持卡者按原说明可以越过建图积分门槛。显式选图和随机开局使用
  同一资格判断，避免随机房绕过限制。
- 53 件带明确百分比说明的已装备外观：只对其装备角色增加竞技积分，多个百分比按原说明相加。
- 当前携带宠物的积分天赋和已学习积分技能：`积分之光/积分加加`按百分比相加；
  `积分闪耀/积分多多`按可复现的结算随机判定翻倍，事务重试不会重新抽取。
- 当前携带宠物的糖币、勇气和材料天赋/技能也已接入各自权威事务：竞技糖币在竞技结算中更新，
  勇气进入探险经验，材料加成只作用于本局实际拾取且目录分类为材料的物品。未携带宠物、账号拥有
  但没有装备到当前角色的外观均不生效。
- `4334/4335` 宠物栏扩容按持有式账号容量实现：基础 5 格，分别扩至 15/25 格，以较高容量为准，
  不在领养时重复消费。
- `1077/2235` 盟约书/超级盟约书：创建家族须分别持有 100/1 份；原始说明只要求“拥有”，
  因此当前不在创建成功时扣除。
- 类型化 Boss 召唤资格道具与单人探险卡一样属于“开局资格”族；召唤物目前只检查全员持有，
  不消费库存。一个 Boss 可能需要一件或一组资格物品，因此不能用“物品 ID 数量”推断 Boss 数量。

## 已建档但仍缺协议/数值证据

- `2897` 竞技场参赛点：抢宝场的等级、扣点表和紫钻优惠在不同年代资料中不一致。
- `4052/4055/4058` 糖泡天书：说明是聊天房挂机经验倍率，但当前 5.2 的挂机奖励触发包尚未闭合。
- 宠物的声望和亲密效果：描述和百分比已解析，但当前人物/宠物存档还没有被客户端消费的权威
  声望、亲密奖励事务，保持建档而不挪用 `Honor`、忠诚度或竞技积分字段。

状态含义：`implemented` 表示服务端已有对应触发路径和自动测试；`catalogued` 表示语义已解析但尚未
接入权威状态；`needs_protocol_evidence` 表示连触发或精确数值仍需客户端代码/实机证据。

## 收藏柜状态同步

收藏柜是同一条账号库存的状态视图，不是按数量拆分的第二个背包。`0x0085` 将整条 ITEM_INFO
切换为收藏状态2或可用状态0，`NumOfItem`保持不变。单件条目客户端会自行更新，但叠加条目不会；
服务端因此在成功ACK后经大厅主连接发送绝对`0x081D ITEM_INFO`，保证收藏和恢复两边的数量、
状态同时收敛。
